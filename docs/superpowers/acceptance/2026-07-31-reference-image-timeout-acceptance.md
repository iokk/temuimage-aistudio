# TuLite 参考图长耗时与任务中心验收

**日期：** 2026-07-31  
**范围：** 本地 `http://127.0.0.1:8501/` 的参考图单张、批量出图和任务中心  
**状态：** 本地修补与任务中心验收通过；6533 长请求通道已恢复

## 1. 目标

本轮验收要回答并修复两个问题：

1. 正常需要 70 至 120 秒的参考图生成，是否被 TuLite 本地超时、任务租约或任务中心提前终止。
2. 当前提供商返回错误时，任务中心是否正确保留进度、展示原因，并允许只重试失败项或切换到可用接口。

## 2. 已确认基线

- TuLite 图片 HTTP 请求超时默认值为 `300` 秒。
- 2026-07-31 最近三个失败请求分别约在 `61`、`65`、`65` 秒结束。
- 失败来自上游 `502/503/504` 或网关超时分类，不是 TuLite 等满 `300` 秒后产生的本地 socket timeout。
- 6533 的密钥可以读取且 `/v1/models` 可用；原配置只保存了站点根地址，模型发现会自动补 `/v1`，但正式出图调用没有补，导致两个流程访问了不同接口。
- 最近任务目前没有 `queued` 或 `running` 状态，因此任务中心当前不是被遗留运行任务占满。
- `task_runners` 存在大量过期记录；它们不计入运行任务槽位，但属于需要清理的运行时数据卫生问题。

## 4. 测试驱动顺序

1. 用保留的真实参考图复现当前接口，记录开始、结束、耗时和终态。
2. 用相同输入测试备用接口，区分应用缺陷和上游网关限制。
3. 先添加失败回归测试，覆盖全部失败任务的终态、错误去重、上游超时说明和 runner 清理。
4. 只修改通过上述测试所需的代码。
5. 运行聚焦测试、完整测试、编译和静态检查。
6. 通过任务引擎提交真实单张和批量任务，至少重复三轮。
7. 在任务中心核对状态、结果、重试动作和日志，再提交本轮修补。

## 5. 发布门槛

以下任一情况存在时，本轮不得标记完成：

- TuLite 在上游仍处理时于 70 至 120 秒内主动终止请求。
- 任务中心丢失任务、错误显示为成功、成功图片被失败项覆盖，或重试会重复生成成功项。
- 错误信息无法区分上游约 60 秒网关限制与本地 300 秒等待。
- 没有至少一次真实参考图成功证据，且未明确证明阻塞来自全部已配置上游。
- 聚焦测试、完整测试、编译或健康检查失败。

## 7. 系统复盘

### 7.1 根因

1. TuLite 的图片请求等待上限本来就是 `300` 秒，任务引擎也会持续心跳，因此用户观察到的 `70` 至 `120` 秒正常出图时间不会被本地任务中心主动截断。
2. 当前 `ioio-gpt-image-2` 中转在本轮失败样本中稳定于约 `62` 至 `65` 秒先返回网关超时。是否能完成取决于上游能否在该网关时限内返回；本地把等待值继续加大没有作用。
3. 原任务中心的失败项重试会复制旧任务中的 `provider_id` 和 `model`。即使用户切换当前提供商，历史失败任务仍会走旧通道，因此表现为“切换了没用”。
4. 智能组图全部失败时会再次抛出汇总异常，导致结构化失败项和原始耗时不够稳定地留在任务中心。
5. 6533 保存的是 `https://img-cn.65535.space`。模型发现通过独立辅助函数访问 `/v1/models`，正式 OpenAI 客户端却直接拼接 `/images/edits`，导致健康检查和真实调用路径不一致。
6. OpenAI 客户端把 HTTP 401 和 403 合并为“API Key 无效或没有访问权限”，任务中心再把包含 `API Key` 的文本统一缩写为“API Key 无效或未配置”，掩盖了接口路径或模型权限问题。

### 7.2 修补与结构优化

1. 失败项重试接口增加显式 `provider_id` 和 `model` 覆盖，任务中心提供对应选择器，并在创建任务前验证启用状态、Key 和模型。
2. 每个智能组图请求独立记录耗时；全部失败也返回可恢复的 `partial` 结果，不再制造第二份异常。
3. 任务中心新增统一的路由摘要，活动任务和最近任务都显示实际提供商、模型和任务 ID。
4. 把失败项重试控件提取为单独模块接口，集中选择、验证和提交逻辑，提高调用侧的简洁度与维护时的局部性。
5. 任务存储增加过期 runner 的定期清理，保留短期诊断窗口但避免长期堆积。
6. 诊断脚本支持临时覆盖提供商和模型，同时深拷贝配置，避免探针污染已保存设置。
7. 新增 OpenAI Base URL 规范化入口：根地址自动补 `/v1`，已有 `/v1` 和自定义代理路径保持不变；历史配置读取、新配置保存和客户端运行时均有覆盖。
8. HTTP 401 明确提示密钥无效，HTTP 403 明确提示提供商拒绝模型或接口访问，避免再次把路由问题归因于密钥。

### 7.3 保留的安全选择

- 图片请求不做同一请求的立即自动重试，避免上游实际已生成但响应丢失时产生重复计费。重试由任务中心按失败项显式触发。
- 不把上游错误 HTML、Base URL 凭据或 API Key 写入任务中心和验收日志。

## 8. 剩余风险与外部动作

- 当前 `ioio-gpt-image-2` 的约 `62` 至 `65` 秒网关限制仍然存在。要稳定支持 `70` 至 `120` 秒参考图生成，需要上游延长网关时限、提供异步任务轮询，或更换可承受长请求的图像接口。
- `6533` 已作为当前提供商恢复，并通过 `71.8` 秒直连探针和 `82.4` 秒任务中心重试。后续风险主要来自第三方接口自身可用性和计费状态，不再是本地 Base URL 路由问题。
